# 非機能要件

この文書は、置き換え後の bot が満たすべき性能、コスト、可用性、セキュリティ、運用の要件を定める。
実現の方法は実装の各タスクで、応答とエラーの文面はインターフェース設計（#29）で決める。

## コスト

- 費用は0円とする。Cloudflare は無料プランのまま運用し、有料プランには移らない。
- 無料枠（Workers AI は1日10,000 Neurons）を超えたら、その日は翻訳を止める。超過分を払って続けることはしない。

無料プランでは無料枠を超えても課金されず、翻訳がエラーになるだけである。
そのため、費用の上限を別に設ける必要がない。

## 入力の上限

| 項目 | 上限 |
| --- | --- |
| `/rt` の本文 | 200文字 |
| 中継言語の数 | 10（要件のまま） |

本文の上限は無料枠から決めた。
中継言語10個で200文字のとき、1回あたり約140 Neurons を使い、1日に呼べるのは約70回と見積もった[^tokens]。
これより長く許すと、数回の呼び出しでその日の無料枠の大半を使ってしまう。

[^tokens]: 1文字を1トークン程度と仮定した見積もり。実際のトークン数は翻訳モジュール（#32）で測り、大きく外れていたら上限を見直す。

## レート制限

- `/rt` は、1人のユーザーにつき1分あたり3回までとする。
- 上限を超えた呼び出しは翻訳せず、時間をおいて試すよう案内する。
- `/settings` と `/help` には制限を設けない。

単位をユーザーにするのは、1人の連打で無料枠を使い切られるのを防ぐためである。
チャンネルやギルドを単位にすると、同じ場所にいる他の利用者まで使えなくなる。
上限は厳密でなくてよい（多少超えて通っても問題にしない）。

## 応答時間

- すべてのコマンドは、Discord の応答期限（3秒）内に応答する。`/rt` は、翻訳中であることを表示して応答する。
- `/rt` は、呼び出しから30秒以内に結果かエラーのどちらかを表示する。翻訳中の表示のまま終わらせない。

## 障害時の扱い

- 翻訳が一時的に失敗したときは、30秒の期限内であれば再試行してよい。
- 翻訳が失敗したら、途中までの結果は表示せずにエラーを表示する。途中までの結果は利用者が読めない言語のままであることが多い。
- エラーは、利用者が次にとる行動に応じて次の2つに分けて伝える。
  - 無料枠の使い切り：その日は使えないこと、日本時間 9:00（00:00 UTC）以降に再度試すこと。
  - それ以外の失敗：時間をおいて再度試すこと。

## セキュリティ

- Discord からのリクエストであることを署名で検証し、検証できないリクエストは処理しない。
- Worker（実行環境）にシークレットを置かない。bot トークンはコマンドの登録にだけ使い、リポジトリに含めない。
- 置き換え後の bot はギルド内の権限も Gateway の intent も必要としない。bot が求める権限と intent は、使わないものをすべて外す。
- bot の応答ではメンションの通知を飛ばさない。`/rt` の本文に `@everyone` などが含まれていても、bot を経由して通知が飛ばないようにする。

## ログと監視

- 失敗の原因（無料枠の使い切り、時間切れ、翻訳の失敗など）を後から調べられるログを残す。
- 原文、翻訳結果、ユーザーを特定する情報は記録しない。障害の調査には文字数、段数、所要時間などで足りる。
- 自動の通知は設けない。障害には利用者からの報告で気付き、ログで原因を調べる。
- 時間切れや無料枠の使い切りが増えていないかを定期的に確かめ、増えていたら入力の上限、レート制限、処理方式を見直す。
