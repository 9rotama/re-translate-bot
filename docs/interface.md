# インターフェース設計

この文書は[リプレース要件](./requirements.md)で定めたコマンドについて、利用者から見える形を定める。
実現の方法は[アーキテクチャ](./architecture.md)と実装の各タスクで扱う。

## コマンド

| コマンド | 引数 | 説明文 |
| --- | --- | --- |
| `/rt` | `text`：再翻訳する文章 | 文章を再翻訳して表示します |
| `/settings show` | なし | このチャンネルの中継ルートを表示します |
| `/settings relay` | `langs`：言語コードを空白区切りで入力（例: en fr de） | 中継言語を設定します（10言語まで） |
| `/settings origin` | `lang`：言語コード（例: ja） | 原文の言語を設定します |
| `/help` | なし | 使い方を表示します |

- 引数はすべて必須とする。
- `/settings` 自体の説明文は「このチャンネルの翻訳設定」とする。
- `text` は200文字まで入力できる。
- コマンドはサーバーのチャンネルでだけ使える。bot との DM には出さない。
- `/settings relay` と `/settings origin` は誰でも実行できる。

## 入力の規則

### 言語コード

- 大文字と小文字を区別しない（`EN` は `en` として扱う）。表示は小文字にする。
- 区切りの空白は全角スペースや連続した空白でもよい。
- 使える言語コードは m2m100 の対応言語（[一覧](https://huggingface.co/facebook/m2m100_1.2B)）とする。

### 同じ言語が続く中継ルート

中継ルート（原文の言語 → 中継言語1 → … → 中継言語N → 原文の言語）で、隣り合う2つが同じ言語になる設定はできない。
たとえば原文の言語が `ja` のとき、中継言語に `ja en`、`en en`、`en ja` は設定できない。
`en fr en` のように隣り合わない重複は設定できる。

同じ言語の間の翻訳では文章がほとんど崩れず、時間と無料枠を使うだけになるからである。

この規則は `/settings origin` にも当てはまる。
中継言語が `en` のチャンネルで原文の言語を `en` にするには、先に中継言語を変える必要がある。

## 公開範囲

| 応答 | 見える人 |
| --- | --- |
| `/rt` の結果と、翻訳中に起きたエラー | チャンネルの全員 |
| `/settings relay`、`/settings origin` の成功 | チャンネルの全員 |
| `/settings show`、`/help` | 呼び出した本人だけ |
| 上記以外のエラー | 呼び出した本人だけ |

設定の変更を全員に見せるのは、設定がチャンネルの全員の `/rt` に効くからである。
`/settings show` と `/help` は本人が確かめるためのものなので、チャンネルに残さない。

## 応答

`/rt` の結果は Embed で、それ以外の応答（エラーを含む）は Container で表示する。
`/rt` は author とフッターで投稿者のアイコン付きの名前と中継ルートを小さく添える必要があり、Container にはこれに当たる部品がない。
それ以外の応答は見出しと本文だけで足り、Container なら本文に見出しや区切り線を使える。

どちらも色は付けない。
中継ルートは ` -> ` で区切って表示する（例: `ja -> en -> ja`）。
`/rt` ではフッターに、それ以外ではコードブロックに入れる。

Container の出力例では、区切り線を `---` の行で表す。

### `/rt`

| 項目 | 内容 |
| --- | --- |
| author | 呼び出した人の名前とアバター |
| 本文 | 再翻訳した文章、空行、`\|\|原文: {原文}\|\|` |
| フッター | 呼び出した人のアバターと中継ルート |

名前はサーバーのニックネーム、表示名、ユーザー名の順で、最初にあるものを使う。
アバターはサーバー用のアバターがあればそれを使う。

原文に `||` やコードブロックなどの記号が含まれていても、スポイラーが途中で切れないように表示する。
翻訳中は Discord の「考え中」の表示が出て、翻訳が終わるとその表示が結果に置き換わる。

### `/settings show`

````markdown
### 中継ルート
```ja -> en -> ja```
````

未設定のチャンネルでは既定値のルートを表示する。

### `/settings relay`、`/settings origin`

`/settings relay` の例（`langs` に `en fr` を指定）:

````markdown
### 中継言語を設定しました
```ja -> en -> fr -> ja```
````

`/settings origin` の例（`lang` に `ko` を指定）:

````markdown
### 原文の言語を設定しました
```ko -> en -> fr -> ko```
````

全員に見える応答なので、何を変えたかを見出しで区別する。

### `/help`

```markdown
### 使い方
`/rt [文章]`
文章を再翻訳して表示

`/settings show`
このチャンネルの中継ルートを表示

`/settings relay [言語コード]`
中継する言語を設定（空白区切りで10ヶ国語まで）

`/settings origin [言語コード]`
原文で使用する言語を設定
---
言語コードの表 → https://huggingface.co/facebook/m2m100_1.2B
```

## エラー

エラーは見出しを `### エラー` とし、その下にメッセージを置く。
どのエラーでも設定は変わらない。
`{}` の部分は実際の値に置き換える。

```markdown
### エラー
言語コードを入力してください
```

### 入力の誤り

| コマンド | 場面 | メッセージ |
| --- | --- | --- |
| `/settings relay`、`/settings origin` | 言語コードが空 | `言語コードを入力してください` |
| `/settings relay` | 言語コードが11個以上 | `中継言語に設定できるのは10ヶ国語までです` |
| `/settings origin` | 言語コードが2つ以上 | `原文の言語は1ヶ国語のみ入力してください` |
| `/settings relay`、`/settings origin` | 対応していない言語コード | 下の例を参照 |
| `/settings relay`、`/settings origin` | 同じ言語が続く | 下の例を参照 |
| `/rt` | 本文が空白だけ | `文章を入力してください` |

対応していない言語コードは1つずつではなくすべて挙げ、直しては再実行する手間を省く。
例（`/settings relay` の `langs` に `en xx yy` を指定）:

```markdown
### エラー
対応していない言語コードがあります: `xx`、`yy`
言語コードの表 → https://huggingface.co/facebook/m2m100_1.2B
```

同じ言語が続くときは更新後のルートを示し、どこが続いているかを読み取れるようにする。
例（原文の言語が `ja` のチャンネルで、`/settings relay` の `langs` に `ja en` を指定）:

````markdown
### エラー
同じ言語が続くルートは設定できません
```ja -> ja -> en -> ja```
````

### `/rt` の利用制限と失敗

| 場面 | メッセージ |
| --- | --- |
| 短時間に使いすぎた（1人1分3回を超えた） | `短時間に使いすぎています。1分ほど待ってから試してください` |
| その日の無料枠を使い切った | `今日の翻訳の上限に達しました。日本時間 9:00（00:00 UTC）以降に試してください` |
| それ以外の翻訳の失敗 | `翻訳に失敗しました。時間をおいて試してください` |

翻訳の失敗（下の2つ）は「考え中」の表示を置き換えるため、チャンネルの全員に見える。
このときはメッセージの下に区切り線を挟んで原文をスポイラーで置き、利用者が打ち直さずに再試行できるようにする。

```markdown
### エラー
翻訳に失敗しました。時間をおいて試してください
---
||原文: {原文}||
```

### 設定の失敗

| コマンド | 場面 | メッセージ |
| --- | --- | --- |
| `/settings show`、`/settings relay`、`/settings origin` | 設定を読み書きできなかった | `設定の読み書きに失敗しました。時間をおいて試してください` |

`/rt` で設定を読めなかったときは、翻訳の失敗として扱う。

### 保存済みの設定の誤り

設定は保存する前に検証するが、検証の漏れや対応言語の変更で、保存済みの設定が上の「入力の誤り」に当たることがありうる。
設定し直せば直るので、設定の読み書きの失敗とは分け、何がおかしいかと直し方を示す。
`/settings show` と `/rt` で、この場面になったときに出す。
公開範囲は、`/settings show` では呼び出した本人だけ、`/rt` では翻訳中のエラーと同じくチャンネルの全員とする。

対応していない言語コードがあるときは、すべて挙げる。

```markdown
### エラー
このチャンネルの設定に、対応していない言語コードがあります: `xx`
/settings relay か /settings origin で設定し直してください
---
言語コードの表 → https://huggingface.co/facebook/m2m100_1.2B
```

同じ言語が続くときは、保存済みの設定のルートを示す。

````markdown
### エラー
このチャンネルの設定は、同じ言語が続くルートになっています
```ja -> ja -> en -> ja```
/settings relay か /settings origin で設定し直してください
````

`/settings relay` と `/settings origin` は、保存済みの設定の誤りを直すためにも使うので、誤りが保存済みの側にだけあるときは断らずに入力を保存する。
たとえば原文の言語に対応していない言語コードが保存されたチャンネルでも、`/settings relay` で中継言語を変えられる。
断ると、原文の言語と中継言語の両方に誤りがあるチャンネルは、どちらのコマンドでも直せなくなるからである。
保存した後も誤りが残っている場合でも、保存はできているので、成功の応答をチャンネルの全員に見せる。
ルートはまだ組み立てられないので、見出しの下にはルートの代わりに、残っている誤りと直し方を上の例と同じ文面で置く。
例（原文の言語に `zz` が保存されたチャンネルで、`/settings relay` の `langs` に `en` を指定）:

```markdown
### 中継言語を設定しました
このチャンネルの設定に、対応していない言語コードがあります: `zz`
/settings relay か /settings origin で設定し直してください
---
言語コードの表 → https://huggingface.co/facebook/m2m100_1.2B
```

入力そのものの誤りと、入力を含む隣り合う2つが同じ言語になる場合は、これまでどおり「入力の誤り」として断る。
